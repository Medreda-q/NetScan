1. EXECUTIVE SUMMARY & IDENTITY
===============================================================================
- What is NetScan?
  NetScan is a dual-tier, unsupervised machine learning network intrusion and anomaly detection system (NIDS). It captures and analyzes raw network packets in real-time (live sniffing via Npcap / libpcap) and offline (forensic .pcap/.pcapng inspection) to detect both microscopic packet malformations and macroscopic stealth attacks without relying on attack signatures or pre-labeled datasets.

- Core Problem Addressed:
  Traditional signature-based NIDS (Snort, Suricata) and single-packet firewalls suffer from a critical blind spot: they are completely blind to RFC-compliant stealth attacks (such as nmap -sS TCP SYN stealth scans) and Zero-Day threats. In a stealth SYN scan, each packet has valid sizes, legal flags, and normal inter-arrival times. The anomaly does not exist within the individual packet; it exists solely in the spatial-temporal behavioral correlation of the source host.

- Primary Technical Innovations:
  1. Dual-Layer Multi-Scale Engine: Microscopic per-frame anomaly scoring (Layer 1) paired with macroscopic 5-second behavioral window aggregation (Layer 2).
  2. Mathematical Port Diversity Ratio (Ratio > 0.5): An exact mathematical signature cleanly separating reconnaissance port sweeps from volumetric DDoS floods.
  3. « Calibrate-Then-Monitor » Mode: A 120-second dynamic baseline learning phase that models the environment's legitimate traffic distribution, eliminating operational false positives before continuous monitoring begins.

===============================================================================
2. PROBLEM STATEMENT & THEORETICAL LIMITS
===============================================================================
- The Signature Blind Spot (Zero-Day Threats):
  Signature-based NIDS operate by matching packet payloads or headers against known attack byte patterns. Any zero-day vulnerability, metamorphic shellcode, or non-standard probing technique has no existing signature and bypasses the firewall completely.

- The Single-Packet Inspection Fallacy:
  An attacker executing nmap -sS -Pn (TCP SYN Half-Open Stealth Scan) sends one standard TCP SYN packet (40-60 bytes) per targeted port and terminates or abandons the handshake upon receiving SYN-ACK. Viewed in isolation, each packet is 100% compliant with RFC 793. Deep Packet Inspection (DPI) and per-packet firewalls judge each packet as legitimate, missing the systematic reconnaissance.

3. MULTI-SCALE DETECTION ARCHITECTURE
===============================================================================
NetScan processes traffic through two complementary unsupervised machine learning layers:

- Layer 1: Microscopic Inspection (Per-Packet)
  * Algorithm: Isolation Forest (contamination=0.05, random_state=42) with StandardScaler.
  * Input Features: Length (total frame size in bytes) and Timestamp (inter-arrival timing offset).
  * Target Anomalies: Jumbo frames (> 1500 bytes MTU fragmentation anomalies), TCP RST / Retransmission storms, and corrupted packets or severe latency outliers (> 95th percentile).
  * Advantage: Blazing fast, minimal memory footprint.

- Layer 2: Macroscopic Behavioral Analysis (Time-Windowed)
  * Algorithm: Isolation Forest (contamination=0.10, random_state=42) with StandardScaler.
  * Temporal Grouping: Sliding micro-windows of 5 seconds, grouped by source IP address (Src_Address).
  * 5-Dimensional Behavioral Vector:
    1. packet_count: Total packets dispatched by the source host in the 5s window.
    2. avg_packet_length: Mean byte length of packets across the window.
    3. unique_dst_ports: Total distinct destination ports contacted.
    4. unique_dst_ips: Total distinct destination target IP addresses reached.
    5. syn_count: Total TCP SYN frames sent without corresponding ACK.
  * Advantage: Unmasks coordinated, multi-target, stealthy scanning activities invisible at the frame level.

===============================================================================
4. MATHEMATICAL SEPARATION HEURISTIC
===============================================================================
Port Diversity Ratio = unique_dst_ports / packet_count

Classification Rules:
- If Ratio > 0.5 ===> PORT SCAN (e.g. nmap -sS)
  Explanation: Attacker probes dozens or hundreds of different ports with only 1 packet each. High port diversity relative to volume.
- If Ratio <= 0.5 ===> VOLUMETRIC FLOOD / DDOS (e.g. SYN flood)
  Explanation: Attacker saturates a specific port or service with a high packet volume. Low port diversity relative to volume.
- Baseline Normal:
  Standard web (HTTP/HTTPS) and DNS traffic shows moderate volumes with low diversity ratios (0.02 to 0.25).

===============================================================================
5. OPERATIONAL WORKFLOW: « CALIBRATE-THEN-MONITOR »
===============================================================================
1. Phase 1 — Dynamic Calibration (Default: 120 Seconds):
   Passive sniffing on the selected network adapter. Computes empirical mean and variance of legitimate background traffic. Fits session-specific StandardScaler and IsolationForest instances. Displays countdown: "Learning normal traffic... X seconds remaining".
2. Phase 2 — Continuous Real-Time Surveillance (Every 5s Window):
   Streams incoming packets, aggregates 5-second windows, extracts the 5D vector, and evaluates deviation against the calibrated baseline.
3. Phase 3 — Instant SOC Notification & Active Containment:
   Dispatches structured Discord webhook notifications (threat class, source IP, targeted port count, packet volume, containment status). Outputs ready-to-run kernel firewall drop commands (iptables on Linux, netsh on Windows). Generates executive forensic report (PDF/HTML) compliant with NIST SP 800-61.

7. SOFTWARE ENGINEERING & SYSTEM RESILIENCE
===============================================================================
- Windows Asyncio Subprocess Crash Resolution:
  Under Windows with Python 3.8+, pyshark (which invokes tshark subprocesses) crashes with RuntimeError: Event loop is closed due to the default ProactorEventLoop. NetScan explicitly enforces asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy()) at startup, eliminating all crashes.
- Dual-Driver Capture Abstraction:
  Supports Npcap (WinPcap mode) on Windows and native libpcap on Linux. Automated self-check via python netscan.py --check.
- Interactive SOC Dashboard:
  Built with Python Streamlit (dashboard.py), featuring real-time KPI cards, PCAP file upload analysis, live stream monitoring, Discord webhook previewers, and persistent forensic JSON/CSV audit logging.

8. KEY PRESENTATION TALKING POINTS & JURY DEFENSE
===============================================================================
- Why Isolation Forest instead of k-Means or SVM?
  Isolation Forest isolates anomalies instead of profiling normal points. Since anomalies in network traffic are 'few and different', they are isolated close to the root of the tree with very short path lengths E(h(x)). It operates in linear time complexity O(n log n), essential to keep decision latency under 12 ms in live streaming.
- What happens if an attack occurs during the 120s calibration phase?
  The calibration phase assumes a clean baseline. In enterprise deployment, calibration is performed during low-traffic maintenance windows. Additionally, outlier filtering within Phase 1 rejects extreme spikes before fitting.
- Future Roadmap & Perspectives:
  1. Kernel-Level Dropping via eBPF / XDP: Moving packet drops directly into the network card driver layer (NIC) to block multi-gigabit DDoS attacks at line-rate.
  2. TLS 1.3 Encrypted Traffic Inspection: Using Deep Learning Autoencoders to analyze packet length sequences and inter-arrival entropy without decrypting payloads.
  3. AI Explainability via SHAP Values: Providing SOC analysts with mathematical feature contribution breakdowns for every alert.
